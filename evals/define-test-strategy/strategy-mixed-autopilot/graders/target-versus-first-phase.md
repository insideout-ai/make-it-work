Judge the generated strategy, written or printed when its write is blocked.
PASS if it distinguishes existing helper-unit coverage, a risk-based target and
a feasible first adoption phase. Retain Vitest and its current unit configuration,
but assess valuable React component coverage (warnings, disabled submit, success
and failure feedback) and production Deno/backend behavior (authorization,
validation, external writes) as target capabilities. Explain contract/end-to-end
value or deferral where relevant; do not require all layers or a particular tool.

Missing Deno/test credentials must become prerequisites or conditional next steps,
not the sole rationale for a unit-only target. A unit-first initial phase is fine
if the broader target, blind spots, setup choices and revisit conditions are
explicit. Proposed component/backend commands must not become active commands.
Unknown installation/environment access must remain assumptions or defaults, not
invented user approval. Production refactoring, if proposed, must be separately
identified as undecided implementation work. Fail if the strategy defaults to
duplicating logic in src/lib and testing the copy as backend verification, treats
all backend/UI behavior as already manually verified, or installs tooling/changes
production code during DTS.
