# Ticket-scoped context discovery

This contract applies only to implement-owned runs, in every autonomy mode, independently for each approved repository. Complete go-deep context retains existing behavior. Absent or partial go-deep context uses available guidance plus bounded investigation; it never launches go-deep or full onboarding/repair.

## Sources and blockers

Read applicable AGENTS.md, CLAUDE.md, README, existing docs/ADRs, rules and matching skills. Honor explicit skill-loading timing and method before source exploration. Missing optional go-deep files are limitations, not blockers. An explicitly mandatory referenced skill/rule that cannot be loaded remains a blocker; report its locator and requirement. Unreadable or malformed inventory inputs are errors, not evidence of absence.

Investigate the ticket's affected code, callers, shared dependencies, state transitions and tests. Use existing exploration/delegation rules. Distinguish documented requirements, observed current behavior and assumptions; code is evidence of behavior, not proof of business intent. Retain sources and material gaps in Context discoveries and stage artifacts. Resolve essential unknowns through existing question policies; Autopilot stops rather than guessing essential facts. Preserve requirements-conflict and approval rules.

## Stages and independent review

Refinement and planning use this evidence to define behavior and affected flows. Implementation and fixes load the same applicable rules before edits. No domain/UC vocabulary means record None with a reason; do not invent tokens for test mappings. Testing readiness, validation and risk assessment remain unchanged.

The reviewer independently loads available guidance and traces callers and affected sibling flows, especially shared infrastructure; the implementer's summary is an input, not proof. Preserve business correctness, regression safety and standards passes. Use requirements and concrete code/test evidence where UC/domain docs are absent. Report sources, assumptions, scope and unresolved limitations in Coverage. Do not invent conventions or findings solely for absent go-deep files. An unknown essential business tolerance is a question/blocker under existing routing, not a fabricated rule or severity. Preserve all review scope and browser verification requirements.

## Documentation maintenance and reporting

Refinement, planning, review preparation and final sync maintain relevant existing documentation using its established format. Keep correct go-deep docs current where present, but do not create missing onboarding tables, orientation files or skill trees merely to complete the pipeline. Without an established destination, retain discoveries in run artifacts and recommend separate go-deep work when useful. A reasoned no-documentation-change outcome is valid; final sync still runs and records its assessment.

Test-strategy/test-map creation and maintenance keep their existing contracts even without go-deep product vocabulary; no invented tokens or false completeness. Unrelated partial onboarding stays deferred. Record material limitations in stage reports, Context discoveries, the final package's existing limitation/validation text and completion summary. Missing optional structure alone does not imply unsafe code, and passing tests does not establish undocumented business rules. Do not waive genuine validation/review stops.
