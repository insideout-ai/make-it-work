### Execute

Pass [compilation evidence and branch provenance](../compilation-evidence.md) through Execute to step executors when reporting existing checks. This clarifies evidence and qualifications only; it adds no gate or unrelated fix work.

Set `execution: running`, then follow `execute` inline with the plan path and the autonomy level. Under `autopilot`, append `--autopilot`, which also makes its completion gate invoke `run-regression --autopilot`. For a participating dashboard, pass the exact state-file path `make-it-work/<TICKET>/<TICKET>-state.md` as execute's dashboard state path; if this is an older resumed run with no dashboard, omit it to preserve the no-backfill rule. `execute` owns the required render immediately after every durable step/batch Progress advance, so the same execution session that verified the step cannot dispatch the next one with a stale dashboard. Whenever the next not-yet-done step's own number is greater than `M − fix_plan_round_steps` (i.e. it belongs to the current fix-plan round's own added steps, not the original plan) — a plain comparison against numbers already in the state file, so this stays correct across an interrupted-and-resumed execute within the same round without depending on which Transition-table row most recently fired — also pass `fix_plan_dispatch`'s current value (`sequential` or `parallel`) as an additional input to `execute`. For the original plan's own steps (resume point at or below that boundary), never pass this input at all. Also, when execution mode is first chosen for this plan version, apply the controller's `execution-mode` event before the first per-step dispatch. It owns the plan Mode/pause update, state fields and audit decision together; a generic decision row does not set execution mode. See references/controller.md for its payload. Read its outcome lines:

- For a version 1 run, read `outcome`, `discoveries`, `failing_tests`, and `gate` (`full-suite`, `scoped+full`, or `none` for `VERIFIED_MANUALLY`) from the validated handoff and record the corresponding execution state; use `failing_tests` as Gate triage input. `VERIFIED_MANUALLY` records `execution: verified-manually` and `gate: none`; its validated evidence permits Review without a late manual-fallback question. When `verification_version: 1`, also pass that marker, `acceptance_evidence_version` when present, the ticket, plan version, and artifact root to `execute`. Read and validate its `artifacts.verification` path; a missing ledger is a stop, not a prose fallback.
- For an older run, use `Execute outcome:`, `Discoveries:`, and `Failing tests:` from the prose report, and record `gate` from the `run-regression` report's leading `Mode:` line (`Full suite` → `full-suite`, `Scoped` → `scoped`, `Scoped + full` → `scoped+full`).

For an older run, save execute's terminal report (whichever stop, gate, or final report it printed) together with its outcome lines to `make-it-work/<TICKET>/<TICKET>-execute.md`, overwriting any earlier one. For a `handoff_version: 1` run, `execute` saved that same report before writing its handoff; read it and do not overwrite it. In either case record that path in `execute_report`. This is the feedback replan and fix-plan (gate) read, so it must survive a pause or an interrupted session.

A missing or unreadable outcome line is treated as `EXECUTE_STOPPED` only for an older run; a version 1 run treats an absent or invalid handoff as a validation error.

If the user explicitly asks to continue without unavailable supplemental manual checks, use `waive-manual-verification` from references/controller.md, then execute's `waive-manual` action. This resumes only a final manual-verification step after implementation is complete, retains the original plan and unverified ACs, and still requires the configured automated completion gate before review. Never reword the plan into a record-only step or use `manual_evidence_complete` for checks not performed. Correctness stops, failed gates and all-manual verification gates remain subject to their existing routes.

If the developer accepts the existing `GATE_NO_RESULT` manual-walkthrough route in a `verification_version: 1` run, update only the ledger's `gate` to `mode: none`, `result: manual-accepted`, with the decision and actual manual walkthrough in `note`; keep ACs without passing manual step evidence marked `unverified`. Validate the ledger again. This records the existing decision, not a new validation phase or an inferred pass.

### Gate triage (on `GATE_FAILED`)

Classify every failing test that is not already listed under Known regressions:

- **Related** — the plan names it (in a step's `**Tests:**` field or a `## Test Plan` row), it lives in a file listed in the plan's Affected Code, or its actual test identity has a current evidence-backed relationship in the product repo's test map to a token in Domains/UCs Touched. Follow `<base>/../../docs/test-map-contract.md` to inspect/refresh affected mappings before classification; stale or ambiguous evidence is Uncertain, never automatically Unrelated. Missing/malformed maps under the current strategy use temporary discovery without source/test annotations; an older strategy needs regeneration and cannot establish an Unrelated classification.
- **Unrelated** — none of the above.
- Suites under `Not run:` are never triaged.
- **Uncertain** — the evidence points both ways, or the failing test can't be identified. Ask the user about each one (related → fix it / unrelated → document it) in both interactive autonomy levels; under `autopilot`, stop rather than classifying it.

Append every unrelated test to Known regressions as a bullet `- <repo>: <file> — <test>`, and append the final related / unrelated split to the file `execute_report` names. Unrelated regressions are documented, never fixed in this run. A gate whose only failures are recorded this way can still be packaged; the final package marks its validation as an accepted failed gate, and Final approval lists them for explicit acceptance. In Guided, also show the final related/unrelated split and ask: **Fix the related ones** / **Treat all as unrelated and continue** / **Stop**. Autopilot follows the already-computed clear split without a second prompt.
